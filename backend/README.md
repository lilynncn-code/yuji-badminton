## 本机启动

在 `backend` 目录使用 Python 3.9 或以上版本：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动前需准备 MySQL，并在仅自己保留的 `backend/.env` 中填写设置。该文件已被排除，不要放进共享代码或截图：

```text
MYSQL_HOST=本机或服务器地址
MYSQL_PORT=3306
MYSQL_USER=数据库使用者
MYSQL_PASSWORD=数据库密码
MYSQL_DATABASE=数据库名称
SECRET_KEY=独立生成并妥善保存的随机长串
APP_ENV=prod
```

`SECRET_KEY` 用于保护登录和验证码记录，不能留空或使用示例文字。更换它会使原登录失效。启动会创建缺少的表，并补齐当前新增字段与约束；操作现有数据前先备份。不要用真实账号或真实用户内容做自动检查。

`GET /health` 返回 `{"status":"ok"}` 只表示进程在响应，不代表短信、地图或视频服务均可用。浏览器可查看 `/docs` 获取各项填写要求。

`./run-local.sh` 供同一 Wi-Fi 的手机调试，会监听所有本机网卡。它在未设置 `APP_ENV` 时使用 `dev`，不要用于公开服务。

## 短信与外部服务

正式短信需填写 `ALIYUN_ACCESS_KEY_ID`、`ALIYUN_ACCESS_KEY_SECRET`、`ALIYUN_SMS_SIGN_NAME`，以及各项 `ALIYUN_SMS_TEMPLATE_*`。注册使用 `REGISTER`，找回密码使用 `RESET_PASSWORD`。实际模板、签名和费用由服务账户提供，代码中不内置私人凭据。

只有 `APP_ENV=dev` 且 `ALLOW_LOCAL_SMS_CODE=true` 时，才使用开发验证码。必须先请求本次用途的验证码；验证码有到期、次数和一次使用限制。正式环境不会返回验证码。真实短信发送请求要求服务端返回验证码，只保存与本次用途绑定的保护值，原文不会返回给 App 或写入记录；校验还会请求短信服务。真实接收与服务账户是否支持该设置仍需检查。

地图使用 `AMAP_KEY`；智能文字建议使用 `DOUBAO_API_KEY`、`DOUBAO_MODEL` 等设置。所有钥匙留在服务端。未配置、查找失败或没有结果时，不提供虚构球馆。文字建议也不代表真正判断了视频里的击球动作。

## 账号与主要功能

除登录、注册、找回密码和健康检查等入口外，私人功能均要求登录。在请求头加入登录结果里的值：

```text
Authorization: Bearer 登录返回的token
```

- 资料：`GET/PATCH /profile/me`，保存头像、背景、城市、俱乐部、持拍手等。
- 球友：`GET /discovery/players`，支持 `page_size`、`keyword`、`city`、`mode`，继续读取使用 `cursor`。返回真实账号及当前聊天申请状态；训练累计数据不等于竞技水平。
- 聊天：`/chat/requests` 申请，经对方同意后才能在 `/chat/chats/{id}/messages` 发消息。语音保存发送者原声，不自动冒充对方回复。消息可以继续读取，未读仅按实际取到的消息更新；对方已读由实际读取记录返回。
- 训练：`POST/GET /training`、`GET /training/summary`、`GET /training/progress`。关卡完成需要达到时长并有动作记录；`request_key` 用于重试时不重复记账。
- 动态：`/posts`，支持继续加载、本人、关注和文字筛选，用户只能删除自己的帖子和留言。
- 关注、屏蔽、收藏与举报：`/social`；获准人员可查看并处理举报，举报人可查结果，正式人员尚未指定。
- 球局：`/games`，可发起、报名、退出、取消和看名单；不代表已经订到场地或付款。
- 训练提问：`/clinic`，可提问、回答、收藏并由提问者选出有帮助的回答；不承诺专业教练必答。
- 球馆：`POST /integrations/amap/courts` 按位置和范围查找；`POST /integrations/amap/courts/city` 按城市和名称查找。两者支持 `page`，返回 `has_more`。价格、营业时间与订场仍需电话确认。

登录七天到期。退出撤销本次登录，改密码或找回密码使旧登录失效。当前部分请求次数限制仍保存在单个进程内，公开部署前需改为各个服务共用。

## 图片、视频与原声

上传统一使用文件字段 `file`；聊天语音使用 `audio`。

| 路径 | 用途与限制 |
|---|---|
| `POST /media/upload` | 图片最多8MB，实际解码检查，最多2000万像素；返回可公开读取的地址 |
| `POST /chat/chats/{id}/images` | 聊天私有图片，未发送仅上传者可看，发送后仅会话双方登录读取 |
| `POST /media/upload-video` | 公开视频最多32MB、5分钟，MP4或WebM；动态或训练提问可引用本人上传的公开视频 |
| `POST /media/upload-training-video` | 私有训练视频，同样32MB和5分钟；返回受保护的 `/media/{id}/file` |
| `PATCH /training/{record_id}/media` | 用 `media_id` 给本人的训练记录附上本人的私有视频 |
| `GET /media/{id}/file` | 仅本人登录可读取训练视频，不使用公开静态地址 |
| `DELETE /media/{id}` | 私有训练视频会清除记录中的视频，保留次数和时长；公开上传移除记录后先登记清理，其他内容仍使用的文件保留 |

视频检查需要系统能找到 `ffprobe`（FFmpeg提供）；未安装会明确拒绝上传，不能跳过检查。网页录制常见的无总时长WebM也会按片段时间检查。图片和公开视频保存在 `backend/uploads/images`、`videos`，私有训练视频在 `private`。不要把整个上传目录公开：服务只公开挂载 `images` 和 `videos`。

`POST /media` 只确认已经上传的本人文件，不能用外部地址伪造上传。`PATCH /media/{id}` 不能更换文件地址、类型或用途，也不能把私有训练视频变为公开动态。

网页训练录像默认关闭、无声音；当前次数来自画面中的举臂或移动，不评判真实击球是否正确。手机训练页目前依靠手动计数与附相册视频，需要实机验证。新上传聊天图片也保存在私有目录；旧版已公开的聊天图片需要另做数据清理，不会因升级自动失效。聊天原声的手机格式与跨手机收听也仍待验证。

## 聊天管理与更换手机号

- `POST /chat/chats/{chat_id}/messages/{message_id}/recall`：只能撤回本人2分钟内发出的消息，返回不含原内容的撤回标记；再次提交不会重复撤回。私有原声或最后一次引用的私有图片随后不可再读取。已被对方另行保存的内容无法收回。
- 读取消息时带 `after_change_id`，会在 `message_updates` 中返回已显示消息的撤回变化；`change_cursor` 是下次继续读取的位置，不能只按新消息编号判断变化。
- `DELETE /chat/chats/{id}/history`：只清空本人看到的历史，不影响对方。`DELETE /chat/chats/{id}` 还会将会话移出本人列表。新消息会重新显示会话，旧记录不恢复。`POST /chat/chats/{id}/visible` 供主动打开聊天使用。
- `POST /auth/change-phone/code`：给当前绑定号码发送验证短信。
- `POST /auth/change-phone/start`：填写当前密码、新手机号和原号码的验证码；通过后给新号码发送验证码，返回5分钟内有效的本次验证编号。
- `POST /auth/change-phone/resend`、`/finish`、`/cancel`：分别重发新号码验证码、确认更换和取消本次验证。验证编号只供本人使用，绑定原号码、新号码和当时的账号状态；改密码会使原验证失效。更换成功保留原账号数据，旧登录全部失效。

自动检查没有发送真实短信，也没有更改真实用户手机号。真实短信、安卓与苹果上的输入和前后台流程仍需检查。

## 消息重试、训练历史和账号注销

- 文字与图片合并发送可带 `request_key`，同账号、同会话的同一次发送只保存一次。相同编号改成不同内容会被拒绝；撤回或单方清空后重试不会恢复旧内容。失败发送及已上传图片按账号和会话保存，重新打开可继续发送；旧手机临时文件若已失效仍需重选。语音发送也支持同一次发送编号，按录音原始内容核对；重复上传会清理多余文件，撤回和清空后重试不恢复。手机保留待发录音供试听、重试或放弃，保存空间不足时临时录音可能失效。
- `GET /training?limit=30&before_id=编号` 分批读取更早的本人训练记录，返回 `has_more`；新增记录不会挤动已经读取的位置。
- `POST /account/deletion/code` 使用独立的 `delete_account` 用途发送验证码，目前使用确认绑定手机号的短信模板，正式使用前须核对模板内容。
- `POST /account/deletion` 核对当前密码、手机验证码和“确认注销”，永久删除本人账号及资料。相关聊天会话和其中双方文件、本人发起球局及名单、本人动态下的互动、本人提问下的回答会一并删除；其他人的独立账号和内容保留。页面先逐项说明范围，再二次确认。已有副本无法收回。
- 注销提交前后会重新核对账号状态；旧登录随账号删除失效。文件先记录待清理名单，再删除文件，失败项保留，可在 `backend` 目录执行 `.venv/bin/python scripts/cleanup_account_files.py` 继续清理。正式服务需安排定期执行及检查未完成项。
- 注销检查只操作临时账号，包含填写错误不删除、账号隔离、相关记录和文件清理、失败后继续清理，以及新账号不能使用旧登录。尚未操作任何真实账号，也未通过网页提交注销。
- 网页读取在连接短暂失败时自动再试一次；写入不自动重试。请求和上传会拒绝换账号前的旧回应，防止覆盖新账号或把新账号退出；检查命令是 `node frontend/scripts/checks/account-and-chat.cjs`（项目外层运行）。


## 留言回复和站内提醒

- 动态详情默认返回最近30条留言；`GET /posts/{id}/comments?before_id=编号` 继续读取更早内容。`GET /posts/{id}?comment_id=编号` 读取提醒目标附近留言。
- 留言可带 `reply_to_id` 指向同一动态中的留言，`request_key` 标识同一次发送；原留言删除后保留回复、停止返回原文，已删除留言不能被原发送重试恢复。
- `GET /notifications` 支持 `before_id`、`limit`、`only_unread`；`GET /notifications/unread` 返回本人未读数量，附带最多100个 `ids` 时只返回仍可查看的这些提醒，供页面更新删除、屏蔽及已读变化。
- `POST /notifications/read` 使用 `ids` 或 `through_id` 二选一；全部已读只覆盖当前已看见的最大编号以前，不误标刚收到的提醒。
- 留言、回复、聊天申请处理、球局报名退出取消、问题回答会保存提醒。自身操作不提醒自己，同一次留言重试和重复处理不重复提醒；取消球局仍提醒当前参加者，包括已屏蔽但尚未退出的人。
- 删除相关内容、账号注销或双方屏蔽后，读取时隐藏相应提醒和原文。提醒表不保存留言或回答原文副本。它不等于手机后台通知，后者仍待接入和双平台检查。
- 本人举报记录改为分批读取，不再只保留前100条可见记录。实际处理入口已补齐；正式处理人员尚未指定。


## 每日基础安排

- `GET /training/daily` 读取按北京时间安排的四组基础练习，返回当天日期、每组说明、时长、次数目标及本人已保存状态。按星期轮换，不判断击球正确性。
- `POST /training/daily/{日期}/{组编号}` 填写 `duration_seconds` 和 `reps`。按顺序核对时长和次数后保存普通训练记录，不完成学习关卡，也不增加学习分；同账号、日期和组只保存一次。通用训练保存入口不能冒用每日保存编号。
- 每组保存后可在本人训练历史查看；暂停和未保存进度在本机按账号、日期保存，其他设备只能看到已经保存的组。日期变化后不能新建旧日组，已有旧日保存请求可确认已有结果。
- 自动检查通过了四组顺序、目标约束、重试、换日和账号隔开；网页只实际走过第一组计时、暂停恢复、填写临时检查次数保存及进入第二组，不代表真实身体练习或真机检查。
- 隔离网页预览使用 `backend/tests/preview_server.py`，默认只监听127.0.0.1:18000，记录和文件均在临时目录；退出后丢弃。用 `VITE_API_BASE_URL=http://127.0.0.1:18000` 生成专用检查页面，避免和常用服务混用。


## 举报核查与处理

- 设置页的“处理举报”只向获准账号显示。普通账号、未登录者及被收回权限的账号均无法读取或处理举报；修改本人资料不能获得此权限。与本人有关的举报须交由其他处理人员核查。
- 可以查看当时文字与当前文字、分批读取等待和已处理记录。处理时须填写2至500字依据，支持未发现违规、移除动态或留言、内容已不存在。账号举报可以登记核查结果，此入口不会停用或删除账号。
- 移除动态后保留不可见的编号，防止原发送重试恢复；其下留言停止显示。移除留言后保留其他人的独立回复，停止返回原文及对应提醒。处理和内容变化一起保存，失败一并保留原状；同一处理请求重试不重复，不允许覆盖别人的已保存结果。
- 处理结果和时间可在举报人的“我的举报记录”查看。没有额外发送短信或手机通知；处理记录中的内部账号编号不向举报人返回。注销时清除相应的当时文字、处理人编号和内容作者编号。
- 默认所有正式账号均无处理权限。正式运营者确认人选后，可在 `backend` 目录用 `.venv/bin/python scripts/report_reviewer.py 账号名` 查看权限；明确设置须加 `--set allow --confirm 账号名`，收回用 `--set deny --confirm 账号名`。本轮没有执行真实账号的权限变更。
- 新增举报处理字段、处理权限及动态移除标记，只在临时数据上验证补齐和旧内容保留；尚未修改真实数据。新移除内容的文件处理见文末说明；历史旧文件仍需核对及整理。
- 检查：`node frontend/scripts/checks/report-review.cjs`（项目外层），以及完整服务检查中的 `test_report_review.py`。


## 技术诊所长回答与发送重试

- 详情默认返回最近30条回答，`GET /clinic/{id}/answers?before_id=编号&limit=30` 继续向前读取；新增回答不会挤动已经取得的旧位置。列表只统计回答数量，不再把所有回答逐条取出。
- `GET /clinic/{id}?answer_id=编号` 打开提醒对应回答附近的内容；回答已删除、被屏蔽或属于其他问题时拒绝返回。页面会说明提醒已失效，再显示最新回答；较早的“有帮助的回答”会单独保留，不必翻到最早才能看到。
- 问题及回答支持可选 `request_key`。同账号同次发送只保存一次，内容变化会拒绝冒用；删除后的旧发送不能恢复原问题或回答。发送保护记录与内容及提醒一起保存，失败一并回退。新表 `clinic_sends` 由正常准备过程创建，未改动真实数据。
- 未发送问题和各问题的回答草稿按账号保存在本机；只有确认保存后清理相同的草稿，旧结果不能清除新草稿。注销时按账号清理这些本机记录，服务上也清理相应发送保护记录。本机无法保存草稿和发送编号时会明确报错，不发出可能重复的请求。
- 页面读取、继续读取与保存之间会忽略已经过时的回应；离开后的确认框不能继续删除，换账号不会使用旧输入。网页的检查使用临时生成的回答，不属于真实用户交流。
- 检查：`node frontend/scripts/checks/clinic-draft.cjs`、`node frontend/scripts/checks/clinic-page.cjs` 及完整检查中的 `test_clinic_pages.py`。

历史动态已移除但仍保留上传记录的文件，与未发送草稿可能无法准确区分，必须核对后再处理；没有记录的旧文件也不会自动删。本轮仅检查临时资料，没有对真实上传目录执行核查或整理，不能声称历史公开地址全部失效。
